       `pub async fn lookup_cve_id(&self, cve_id: &str) -> Result<Option<CvssScore>, VulnLookupError>`:
       - GET `https://cveawg.mitre.org/api/cve/{cve_id}`
       - On 404: return Ok(None) (CVE not found, not an error)
       - On 429: return Err(VulnLookupError::RateLimited { retry_after_secs: 30 })
       - On success: deserialize as CveOrgResponse
       - Extract CVSS: search CNA metrics first, then all ADP containers. Priority: V4 > V3.1 > V3.0.
       - If CVSS found in multiple containers, take the highest score.
       - Return Ok(Some(CvssScore)) or Ok(None) if no CVSS anywhere.

       VulnSource impl: `lookup_cpe` returns `Err(VulnLookupError::Empty { cpe })` always -- CVE.org cannot search by CPE.

       **EnrichmentStats struct** (returned from enrich_scan):
       ```rust
       #[derive(Debug, Default)]
       pub struct EnrichmentStats {
           pub services_queried: usize,
           pub services_skipped: usize,  // no CPE
           pub cves_found: usize,
           pub source_failures: Vec<String>,  // e.g., "NVD: rate limited (3 services skipped)"
       }
       ```

       **EnrichmentOptions struct:**
       ```rust
       pub struct EnrichmentOptions {
           pub concurrency: usize,    // D-15: default 5
           pub quiet: bool,           // D-13: suppress progress
       }
       impl Default for EnrichmentOptions {
           fn default() -> Self {
               Self { concurrency: 5, quiet: false }
           }
       }
       ```

       **`pub async fn enrich_scan(scan: &mut ScanResult, nvd: &NvdSource, cve_org: &CveOrgSource, opts: &EnrichmentOptions) -> EnrichmentStats`:**

       The orchestration flow:
       a. Collect all (host_idx, port_idx, cpe_list) tuples from the scan where service has non-empty CPE vec.
       b. Count total services with CPEs (for progress counter). For services without CPEs, increment services_skipped and emit warning to stderr per D-09: `eprintln!("Warning: {port_id}/{protocol} {service_name}: no CPE -- skipping vuln lookup")`
       c. Create `Arc<Semaphore>` with `opts.concurrency` permits (D-15).
       d. For each service with CPEs, spawn a tokio task that:
          - Acquires semaphore permit
          - For each CPE string in the service: call `with_retry(|| nvd.lookup_cpe(&cpe))`
          - Collect all Vulnerability results
          - For each unique CVE ID found by NVD: call `with_retry(|| cve_org.lookup_cve_id(&cve_id))` to get CVE.org CVSS
          - If CVE.org returns a higher CVSS for a CVE, update the Vulnerability's cvss field (per D-08)
          - Print progress to stderr per D-12: `eprintln!("[{n}/{total}] Querying NVD for {product} {version}... {count} CVEs")` (unless opts.quiet)
          - On source failure: record in stats, continue with partial results (D-05)
       e. After all tasks complete, for each (host_idx, port_idx), set port.vulnerabilities = deduped results.
       f. Return EnrichmentStats.

       **`fn dedup_vulnerabilities(vulns: Vec<Vulnerability>) -> Vec<Vulnerability>`:**
       - Group by cve_id
       - For each group, keep the entry with the highest CVSS score (per D-08)
       - If one has cvss: Some and other has cvss: None, keep the Some
       - Return deduplicated vec

       **`async fn with_retry<F, Fut, T>(f: F) -> Result<T, VulnLookupError>` (per D-06):**
       ```rust
       where F: Fn() -> Fut, Fut: Future<Output = Result<T, VulnLookupError>>
       ```
       - Retry delays: [1, 2, 4] seconds
       - Retry on RateLimited and NetworkFailure
       - Do NOT retry on Empty (return immediately)
       - After 3 failed attempts, return the last error

       Note on task structure: Since VulnSource::lookup_cpe uses RPITIT (edition 2024), and NvdSource/CveOrgSource are concrete types (not dyn), the orchestrator takes concrete `&NvdSource` and `&CveOrgSource` references rather than `&[Arc<dyn VulnSource>]`. This avoids object safety issues with RPITIT. The enrichment function calls NvdSource directly for CPE lookup and CveOrgSource for per-CVE enrichment. This matches the architectural insight that CVE.org is a secondary per-CVE enrichment source, not an independent CPE search source.
